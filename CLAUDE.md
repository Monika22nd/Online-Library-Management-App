# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Common commands

### Backend (FastAPI, Python 3.11, MySQL 8)
```bash
export MYSQL_URL="mysql+pymysql://root:@localhost:3306/library_openlibrary?charset=utf8mb4"

pip install -r requirements.txt
alembic upgrade head                       # apply schema + triggers/procs
python -m app.scripts.seed                 # idempotent demo user seed
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```
The startup hook in `app/main.py` re-runs `seed_users()` on every boot — non-fatal if the DB is missing, so the app comes up even before the first `alembic upgrade head`.

### Frontend (React 19 + Vite)
```bash
cd frontend
npm install
npm run dev      # :3000, proxies /api -> http://localhost:8000
npm run build
```

### Migrations
```bash
alembic revision --autogenerate -m "msg"   # rarely useful — see "Migration philosophy" below
alembic downgrade -1
alembic current
```

### Redis (optional)
```bash
docker-compose up -d redis   # only redis is containerized; API + frontend + MySQL run on the host
```
If Redis isn't running, the app falls back to in-memory cart/cache (see `redis_service.py`).

### Tests / lint
None configured.

## Architecture

Three-tier app: React SPA → FastAPI → MySQL + Redis. Everything runs directly on the host; only Redis is containerized via `docker-compose.yml`. Vite's dev server proxies `/api/*` to FastAPI on port 8000 (see `frontend/vite.config.js`).

### Backend layout

- `app/main.py` — **flat route module**, no APIRouter. New endpoints go directly here. Every DB-touching route takes `session: Session = Depends(get_db_session)`.
- `app/models/` — one SQLAlchemy ORM model per entity (`user.py`, `book.py`, `edition.py`, `copy.py`, `loan.py`, `member.py`, etc.). `app/models/__init__.py` re-exports `Base` + every model so Alembic's `env.py` can autodiscover them with a single import. **Adding a model = adding the import to `__init__.py`** or autogenerate misses it.
- `app/services/` — business logic split by domain:
  - `auth_svc.py` (passlib bcrypt, user/member creation)
  - `books_svc.py` (list/get/import — computes `available_copies` via JOIN on `editions` + `copies`)
  - `loans_svc.py` (CRUD + `CALL sp_approve_loan` etc.)
  - `audit_svc.py`
  - `openlibrary.py` (async httpx client; `fetch_and_save_books` takes a session)
  - `redis_service.py` (cart + cache, with in-memory fallback)
- `app/scripts/seed.py` — demo user seeding, runnable as `python -m app.scripts.seed`.
- `alembic/versions/` — two revisions: `0001_initial.py` creates all tables; `0002_triggers_and_procedures.py` runs the trigger/proc DDL via `op.execute()`.

### Migration philosophy

Both Alembic revisions are **hand-written**, not autogenerated. Don't trust autogenerate for new migrations: it misses MySQL ENUMs, `BIGINT UNSIGNED`, `JSON`, the `request_date DEFAULT (CURRENT_DATE)` server default, and never round-trips trigger/procedure DDL. Hand-write new revisions and mirror any DDL changes in `db/sql/triggers_and_procedures.sql` (the human-readable copy).

### Schema invariants enforced in MySQL

- **`trg_loans_check_max`** (BEFORE INSERT on loans): `SIGNAL SQLSTATE '45000'` if member has ≥5 loans in PENDING/APPROVED. SQLAlchemy surfaces this as `IntegrityError` — `loans_svc.create_loan_request` catches it and re-raises as `MaxLoansExceeded`. Routes turn that into HTTP 400.
- **`trg_loans_status_audit`** (AFTER UPDATE on loans): writes to `audit_log` whenever `approval_status` changes. **Don't duplicate this in Python** — every `UPDATE loans` (including from stored procedures) triggers it automatically.
- **`request_date DEFAULT (CURRENT_DATE)`** on the column — replaces the legacy `auto_request_date` SQLite trigger.

### Stored procedures own the loan state machine

`sp_approve_loan`, `sp_return_loan`, `sp_cancel_loan`, and `sp_bulk_approve_loans` live in MySQL. The Python services in `loans_svc.py` are thin wrappers that `CALL sp_xxx(:args)` and re-read the row to confirm state. Two reasons this matters:

1. The procedures use `SELECT … FOR UPDATE` to lock the loan row and the candidate copy row before flipping status — preventing two admins from grabbing the same copy.
2. The full state transition (loan status + `copies.circulation_status` + dates) is one transaction inside the procedure. **Don't reimplement this logic in Python** — modify the procedure and ship a new Alembic revision.

### Loan workflow + inventory model

- `loans.approval_status` = `PENDING/APPROVED/REJECTED/RETURNED/CANCELLED` (workflow).
- `loans.loan_status` = `open/returned/overdue/lost` (physical, set after approval).
- A PENDING loan has `copy_id NULL` and `requested_book_id` pointing at the desired `books.book_id`. `sp_approve_loan` picks the first `copies.circulation_status='available'` copy of any edition of that book and assigns it.
- Cart (Redis) stores `book_id`s. Checkout calls `loans_svc.create_loan_request(member_id, book_id)` per item; user→member is resolved at the route boundary (`user.member_id` must be non-null).

### Auth (intentionally minimal)

- Passwords are bcrypt-hashed in `users.password_hash` (passlib).
- After login, tokens live in a process-local dict `fake_users_db: token → user`. **Demo-grade only** — wiped on restart, no JWT, no refresh. Don't extend this; replace it if real auth is needed.
- `users.member_id` is a nullable FK. Admins are typically created without a member row (can't borrow). Regular users get an auto-created member in `auth_svc.create_user(create_member=True)`.

### Redis-backed features

- **Cart** (`cart:{user_id}` list). The `*_atomic` variants in `redis_service.py` use Lua scripts for race-free check-and-add / checkout. Falls back to module-level dicts if Redis is unreachable at import time.
- **Cache** for OpenLibrary responses (`search:`, `work:`, `trending:`, `subject:`, `author:` keys, 10–60 min TTL).
- **Distributed locks** (`acquire_lock_atomic` / `release_lock_atomic`) — Lua compare-and-delete on release.

### Frontend

- `frontend/src/api.js` — single `request()` wrapper hitting `/api/*` (relative path, works through Vite dev proxy and nginx prod proxy). Also exports `coverUrl(value)` — a thin placeholder fallback for missing covers. Backend services now consistently return ready-to-use OpenLibrary URLs.
- `frontend/src/AuthContext.jsx` — persists `user` + `token` to `localStorage`.
- Routes declared in `App.jsx`; pages in `frontend/src/pages/`, components in `frontend/src/components/`.
- `user_id` and `admin_id` go to backend endpoints as query strings (matches the demo-auth model).
- `frontend/` has stray Vite TS scaffolding (`counter.ts`, `main.ts`, `tsconfig.json`); the actual app is JS — `main.jsx` is the entry, see `vite.config.js`.

### Visual design system

- "Editorial Light" palette: warm paper background (`--paper`), deep ink text (`--ink`), burgundy accent (`--accent: #8b1e2b`), Playfair Display for serif headings, Inter for body.
- Tokens live in `frontend/src/index.css` (`--paper`, `--ink-*`, `--accent`, `--rule`, `--s-{1..9}` spacing scale, `--r-{sm,md,lg}` radius, `--shadow-{sm,md,lg}`, `--status-*-bg/fg`).
- Global utility classes: `.container`, `.section-header`, `.section-title`, `.eyebrow`, `.btn` + `.btn-primary/secondary/ghost`, `.input`, `.badge` + `.badge-{pending,approved,returned,cancelled}`, `.book-grid`, `.skeleton`, `.fade-in`, `.slide-up`. Reuse before adding page-local styles.
- Pages (`Home.css`, `Search.css`, `Subject.css`, `BookDetail.css`, `Cart.css`, `MyLoans.css`, `Login.css`, `AdminPanel.css`) build on those tokens; status colors come from the `--status-*-bg/fg` pairs, not ad-hoc hex.

### Frontend ↔ backend contract

The previous round of FE workarounds (cover URL coercion, missing authors,
title-based import, hidden editions sidebar) has been removed. Backend now
returns:
- `cover_url`: full OpenLibrary URL on both loan and book dicts.
- `author` + `authors[]`: joined from `book_authors → authors`.
- `GET /api/books/{id}` includes `editions[].copies[]`.
- `POST /api/books/import_one` body `{openlibrary_key}` for one-off imports
  from `BookDetail`.

If you change any of these shapes, audit `frontend/src/api.js`,
`MyLoans.jsx`, `Cart.jsx`, `AdminPanel.jsx`, and `BookDetail.jsx` for impact.
